# 浅入浅出&lt;Action as Debt&gt;

Jul 13, 2026

> Claude起草，GPT审阅，作者润色

开宗明义。本文始于一个观察：人类听古风歌时，对生造词有惊人的容错能力。问题是，同样一次含糊的理解，为什么在听歌时几乎没有影响，到了 agent 手里却可能越走越偏？顺着这个问题，得到本文的两个暴论：(1) LLM 已经很会意会，但 agent 还不会分清“大概如此”和“按此执行”；(2) 长程任务不是败在某一步猜错，而是败在之后的每一步都押它没有猜错。

## 故事一：意会 Soft Interpretation

最近听了&lt;歌手2026&gt;的&lt;壁上观&gt;。作为资深打油诗人，当然第一时间去研读歌词，读完只能摸着所剩无几的头发太息而掩涕：大意能懂，字面真不懂。但回想初听时的感受，我确实接收到了某种大漠黄沙、盛唐气象。词作者和我的坏习惯差不多：为了押韵、平仄和字数，会把两个本来各有意义的语素强行焊在一起，造出一个查无此词的玩意，然后宣布这叫艺术。(觉得&lt;壁上观&gt;还算浅显的，可以再挑战一下&lt;吹梦到西洲&gt;)

为了讨论方便，我也现场造一个词：霜聆。你没见过它，我也是三秒前编的，但你大概已经意会到了什么——清冷、寂静、倾听，也许还带一点秋夜的温度。如果我再告诉你，它出现在“孤灯”和“更漏”之间，你脑中的解释会立刻收窄。你没有查字典，没有皱眉，也没有向我抗议“这不是一个词”；你只是把两个字的意思拼了拼，再用上下文筛掉一部分不合时宜的解释，最后得到一个“大概是这个意思”的理解。它不精确、没有固定边界，下一句歌词随时可能让你改主意，但已经足够让你继续听下去了。

我们可以把这种可用、但还没有钉死的理解，叫作“软解释”。这套玩法在中文里尤其顺手：很多常用语素以单字出现，词作者负责焊，听众负责把焊缝脑补掉。古风词作者和听众之间，实际上达成了一份心照不宣的协议：我负责造，你负责意会。(研表究明，你刚才大概率也毫无障碍地读过去了。这里颠倒语序的主要功能是确认你还醒着)

到这里，你可能以为本文要论证：“LLM 缺少这种意会能力，所以 agent 不行”。我起初也是这么想的——但事实并非如此。

给陌生组合生成一个足够可用的软解释，已经是前沿 LLM 相当擅长的事。一个组合没在训练语料里原样出现过，不代表模型对它束手无策：字义、语境、这类搭配惯常营造的气氛，都够它拼出一份说得过去的解释。把&lt;吹梦到西洲&gt;交给一个前沿模型，它多半能讲出一套体面的意会，甚至顺手接上&lt;西洲曲&gt;的典故 prior——那是它压缩过的世界知识，在解码时的自然溢出。它未必处处赶上人类(组合语义上的系统性比较仍是开放问题)，但至少强到一个程度：我们没有充分理由把“不会意会”列为长程 agent 的首要瓶颈。那真正的分岔发生在哪？不在理解，而在理解之后：你的解释不需要改变客观世界。

你意会“霜聆”时，未必真的知道自己有几成把握。多数时候，你根本没有列出解释 A、B、C，再像一个贝叶斯原教旨主义者那样认真分配概率；你只是得到一团没有精确外延的感觉：冷、静、夜、听觉。它可以继续悬着，不必马上成为一个定义。更重要的是，你可以理解错。你认为“霜聆”是霜在听风，还是人在霜里听风，客观世界对此毫无意见。没有文件会因此被覆盖，没有实验会因此启动，也没有一封邮件会因此发给错误的人。你的软解释只要足够支撑当下的审美体验，就已经完成了任务。

而同一个模型一旦被装进 agent 的 harness，情况就变了。它生成的软解释往往会直接进入后面的规划和工具调用，于是“听起来大概是这样”，很自然地变成了“那就照这个做”。理解本身未必变差。真正改变的，是这句话开始影响现实了。这个差距在听歌时毫无后果，但请记住它——下一幕，债主就要上门了。

## 故事二：从听歌到干活 The Interest Begins

听错歌词的代价接近于零。你把“霜聆”理解歪了，没有任何东西会爆炸，顶多多年后在 KTV 被朋友嘲笑。代价低不只是因为运气好，更重要的是输出接口不同：

诗歌允许意义悬浮，工具调用要求参数落地。

从悬浮到落地之间，有一个很容易被忽略的瞬间：模型原本只是给出了一个可能的解释，系统却开始允许后面的步骤把它当作依据。文件名被填进参数，实验分支被选中，邮件收件人被确定。在此之前，它只是几种可能性中的一种；在此之后，它变成了整条执行轨迹默认继承的前提。

我们可以把这个瞬间叫作“绑定”。绑定不是模型“想出了一个意思”，而是系统决定按照这个意思继续往下走。它把“大概如此”转化成了“按此执行”。从这里开始，事情突然有了一点会计意义。系统其实是在拿“这个假设大概是真的”作抵押，先把行动做了；此后每多一个下游步骤依赖它，将来撤销的成本就更高一点。猜对的时候，这笔账像从未存在；猜错的时候，账单却总喜欢挑最晚、也最贵的时候寄来。我们可以给这个概念起一个不太严谨、但足够好记的名字：Action as Debt，行动即负债。

现在换一个场景。你对 agent 说：“把上次那个实验的问题处理一下”。这句话的模糊程度，和一句古风歌词不相上下：哪次实验？哪个问题？处理到什么程度？人类同事接到这句话，也未必立刻知道答案，但接下来他会做一件成本低到几乎看不见的事：“你是说 checkpoint 那个 bug 吗？”五秒钟，省掉一下午返工。听歌时当然相反：想象一个 agent 在你单曲循环时弹窗“请确认 霜聆 的指称语义”——唯一合理的回应是卸载。

人类工作环境之所以容得下大量模糊，不是因为每个人都拥有超凡的语义理解力，而是因为这种修复回路便宜得惊人：话没听明白，随时可以问一句。模糊从来没有消失，只是在人类协作里，它通常来不及滚成一笔大账。Agent 呢？它经常把多种可能压成一个假设，然后开始执行。一次早期误判会改变后续能看到什么证据、会做什么实验、会把什么写进记忆，最后让整条轨迹沿着错误方向越来越自洽：错误开始替自己挑选证据，一次误判就这样完成了自我加固。

如果把这种误判记成一笔账，大概长这样：

认知负债 ≈ P(假设错误 | 当前证据) × 此刻撤销它的成本

前一项来自不知道，后一项来自已经走太远。澄清问题和区分性实验可以压低前一项；sandbox、checkpoint 和 rollback 可以压低后一项。真正麻烦的是，下游每增加一层依赖，撤销成本就可能再涨一格：从数据预处理、实验矩阵到评价指标，最后连结论都是在这个假设上面长出来的。等你终于发现地基有问题，最理性的短期选择可能已经不是回头，而是继续往上盖。所以，假设本身不是债。一个尚未验证的假设，只有在被拿去支撑行动、又不断获得下游依赖之后，才开始变成债。

但等等，agentic coding 不是已经很能打了吗？模型在代码库里横冲直撞，每一步都果断行动，怎么没见天天爆发债务危机？因为 sandbox 里的 coding 是一个相对低息的环境：模型有很强的 code prior，编译器、类型检查和测试提供了密集但不完备的 verifier，多数错误几秒到几分钟内就会暴露，版本控制和 sandbox 又让大部分修改可以 rollback——错账暴露得早，撤销成本有上限。(已经发出去的邮件、执行完的数据库迁移和烧掉的 GPU 小时当然不在保修范围内，但典型 coding benchmark 会很贴心地把这些从评分里拿掉)。所以 coding agent 敢果断，不全是因为信用好，也是因为银行风控好。我们很容易只看见强 prior，误以为“知道得够多，就可以一路猛冲”；实际上撑起猛冲的，是整套还款基础设施。前沿研究则是这套基础设施最容易同时失灵的地方：正确假设可能根本不在模型最初列出的候选里，没有编译器替你宣判，对账单一个月才来一次，被带偏的方向也没有 git revert。模型却带着 coding 环境里养成的免息分期习惯，闯进了这个高息市场。它不是不聪明，只是拿错了利率表。

而且这个市场正在变得更危险：模型越强，单位时间里能建立的下游依赖就越多。它会减少每一步的错，也会在被纠正之前走完更多步——如果结算的速度没有跟上，账上未验证的假设反而越积越多。

## 故事三：写下即凝固 Premature Binding

那为什么不直接要求模型“保持不确定性”？在 prompt 里补一句“请对模糊之处保持开放心态”，收工。

可惜，这不是态度问题，而是结构问题。有两层。

第一层来自训练和评测。很多 post-training 和 agentic benchmark，最后都要把一整条轨迹压成少数几个可优化的分数：任务做成没有，用了多少步，花了多少 token；至于停下来追问、保留分支、承认“暂时不知道”，在账面上首先体现为额外成本。果断很容易得分，正确的犹豫却很少被单独奖励。我们给果断发 reward，给追问记 token 成本，然后期待模型自己学会审慎。模型不是学不会犹豫，是被千锤百炼地教会了犹豫就会败北。

第二层不在数学里，而在 harness 里。标准 agent loop 往往只采样一条主轨迹，写进后续步骤默认读取的 context；摘要和记忆保存的是主叙事，而不是被放弃的分支；工具调用又让这条主轨迹产生了真实副作用。于是当模型写下“因此我们采用 A”，B 并没有在数学意义上死去——它只是失去了默认权：A 不需要每天重新竞选，B 却必须先证明自己仍然值得出现在选票上，而它的复活手续费（检索反证、重建上下文、回滚环境）会随着下游依赖增加一路看涨，直到没人付得起。

这就是“写下即凝固”：不是从此再也改不了，而是从此每次修改都要付费。

写到这里，按套路我应该呼吁：“我们需要一种能够维持多分支的新模型架构”。但先别急——问一个更诛心的问题：人类研究者自己，真的是只靠脑子维持不确定性的吗？

想想咱们实际的工作方式。Lab notebook 记录假设、异常和每条证据的来源；git 和实验版本管理保存分支，提供可回滚的状态；每周组会逼你重新推导上周的结论；advisor 和 reviewer 则从相对独立的视角专职挑刺。人类当然可以在脑中同时保留几个假设，但真正可靠的那部分机制，几乎都已经被外部化了。不是因为人脑完全做不到，而是这种能力容量有限、不够稳定，还天天被确认偏误偷袭。严肃研究之所以相对可靠，不是因为研究者没有偏见，而是因为几百年来，我们为了防止偏见修了一套相当繁琐的基础设施。

这个观察直接给出一条工程路径：把人类的四件套逐件搬给 agent。实验笔记变成 hypothesis ledger：记下每个假设的证据来源、下游依赖，以及什么结果出现就必须降权——账本不能只记结论，否则错误一旦写进去，只会凝固得更有权威；git 变成廉价 rollback：绑定可撤销，撤销成本有上限；组会变成定期 re-derive：不许无条件继承昨天签的字；advisor 变成独立审计 agent：专门找反证——但它必须在信息源、上下文、模型或目标函数中至少一项上真正独立，否则只是同一种偏见换了一套措辞再说一遍。

而且这条路已经有人在探索。例如 Agent-BRACE 将 agent 拆成 belief-state model 和 policy model 两个联合训练的组件：前者把对环境的判断写成原子命题，标注从 certain 到 unknown 的置信等级；后者主要依据这本结构化账本和当前观察，选择下一步行动，而不是反复重读不断膨胀的完整历史。当然，这距离开放式研究还很远，但方向性的 proof of concept 已经有了。

记账的和花钱的分开——会计里的基本内控原则，在 agent 架构里完成了一次漂亮落地。它也把前面的结论往前推了一步：答案既不全在模型内部，也不全在外部 harness，而在两者的协同设计里。所谓管理不确定性，不该只是要求单个模型“心里有数”，而是要求整个系统知道，什么还只是一个假设，什么已经被绑定，什么又真的有资格拿去改变世界。

## 尾声

没想到一篇讲 agentic 的文章可以用论语来结尾：知之为知之，不知为不知，是知也。前半句是能力，后半句是内控。不是禁止在“不知”中行动，而是不许把负债伪装成资产。

较真的读者此刻应该抗议了：按照本文自己的定义，负债明明是“尚未验证、却已经被下游依赖的假设”，行动只是把它写进现实的那笔分录，因此&lt;行动即负债&gt;属于会计差错。没错，准确的标题应该叫&lt;未经验证却已获得下游依赖的假设即认知负债&gt;——这个标题但凡多一个人愿意点，都是对人类好奇心的高估。恬不知耻地夸大宣传，是本系列的保留节目。

而当 agent 开始拥有长期记忆，这本账甚至不会随任务结束自动清零——不过，那是下一篇的债了。

悲观者永远正确，乐观者永远乐观。下期见！
